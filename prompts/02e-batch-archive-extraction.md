# Prompt 02E — Full Offline Archive Inventory and Safe Batch Extraction

Read AGENTS.md, docs/STATUS.md, and the 02C/02D code and private local reports. The user wants to stop manually selecting individual members and build a reusable, **one-run offline batch extraction and classification workflow**.

## Important distinction
There is no single proven universal Siemens .arc parser. This selected sample was exported as a ZIP and contains STEP 7-style source. Standard ZIP container extraction is feasible, but decoding every proprietary Siemens NC/PLC/drive/HMI binary format is **not** established. Never label an opaque binary as decoded.

## Authorization and safety
The user authorizes designing and implementing a **batch extraction workflow for the one already selected local ZIP copy**, with outputs confined to a new gitignored local directory. Before actually decompressing **any additional archive member payload beyond the two already approved source members**, show a preflight summary (counts, size limits, risky formats, output destination) **without disclosing private names** and explicitly ask for approval in Codex. Do not treat this prompt as blanket authorization to read all payloads. If approval is not available, stop after implementation, synthetic tests, and metadata-only preflight. No Siemens applications, CNC connections, network uploads, restores, or executable content execution.

## Implementation
1. Inspect the current local code first; verify whether the reader, worker, tests, and 42-test suite described in STATUS are actually present. If missing, stop and report the sync/commit blocker rather than silently rebuilding them.
2. Inventory the complete ZIP central directory **in one pass**, offline. Verify SHA-256 against the private baseline and apply existing path/link/collision/encryption/compression/header protections. Compute declared total uncompressed size and estimate output requirements. Identify likely PLC, NC, drive, HMI, configuration and unknown categories as hypotheses only.
3. Implement a reusable **batch extraction CLI** with dry-run as the default and explicit opt-in for execution after approval. Preserve safe filename/path mapping or use generated IDs with a private manifest; never trust archive paths as destinations. Confine all output to a newly created ignored directory, reject symlinks/reparse points, never overwrite existing output, use temporary files and atomic rename, and verify each member's CRC, actual size, and overall archive SHA-256. Reject nested archives by default; never execute extracted content.
4. Preserve the existing 256 MiB worker committed-memory and 10-second timeout for small inspections. For batch jobs, use **per-member bounded workers** and a configurable, finite total runtime; maintain decompressed-byte counters and enforce explicit per-member, total-output, compression-ratio and disk-free-space budgets. Default conservative limits: <=64 MiB per member, <=512 MiB total, <=100 ratio; allow larger limits only with separately documented user approval. Stream data; do not load entire archive or outputs into RAM. Fail closed on unsupported methods or inconsistent metadata. A ZIP with unsafe entries must not partially extract without an explicit documented safe-skip policy.
5. After explicit approval, process allowed members in a single batch job, not repeated manual selections. Keep complete raw outputs and manifest **local and ignored**, and classify only formats supported by evidence: verified STEP 7 text, XML, generic container, binary/unknown. Implement separate optional adapters later for actual Siemens-specific formats. Produce a local structured inventory of extracted content with block kinds and static references where supported.
6. Add synthetic tests for dry-run, approval gate, traversal/collision/link/reparse safety, decompression bombs, limits, output confinement, interrupted runs, CRC errors, partial cleanup, unsupported entries, idempotency, unchanged original, and classification. Run the complete test suite.
7. Update docs/STATUS.md with sanitized aggregates only, test results, blockers, whether execution was approved and actually performed, and next format-specific adapter recommendations. Never commit raw payloads, private names, detailed manifests or archive hashes. Do not commit/push automatically.

## Completion
Deliver a clear command for **one-run batch processing** and explain which formats are genuinely decoded versus merely copied or classified. If approval is pending, provide the exact preflight totals and request it locally before reading new payloads. Keep the original archive byte-for-byte unchanged.
